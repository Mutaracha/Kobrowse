# Kobrowse / kofm

Экспериментальный файловый менеджер для Kobo: существующий плагин NickelHook
`kofm` служит основой. Экран ориентируется на приложенные референсы, но
адаптирован к чёрно-белому e-ink: путь, список с пиктограммами, датой и
размером, а во вложенной папке — строка перехода `..`. Долгое нажатие
выбирает элемент; копирование, перенос, корзина, поиск и настройки взяты из
прототипа. Кнопки листания сохранены. Это не полная реализация всех действий,
вкладок и меню со скриншотов.

Проект не является сборкой читалки [kobalt_ru](https://github.com/Mutaracha/kobalt_ru).
Из неё заимствован подход: отдельная сборка тестового пакета, проверка его
содержимого и артефакт CI без автоматической публикации. Плагин пока использует
свой NickelHook и NickelTC для Qt 5; скрипты Kobalt для Qt 5/6 и его формат ZIP
напрямую к этому плагину неприменимы. Поддержка прошивок Qt 6 не заявлена.

## Тестовый пакет без локального Docker

При push в ветку или запуске **Actions → Kobo test package → Run workflow**
GitHub Actions выполняет сборку на своём сервере. После успешного выполнения
архив `kofm_KoboRoot.tgz` доступен в артефакте `kofm-kobo-qt5-test` на странице
запуска. Docker и NickelTC на компьютере пользователя для этого не нужны.
Сам GitHub runner использует готовый образ NickelTC; это не нативная сборка без
SDK. Как и в `kobalt_ru`, CI собирает и проверяет пакет в контейнере, но для
существующего Qt 5 плагина пока используется NickelTC, а не SDK Kobalt.

NickelHook подключён как Git-submodule из `pgaskin/NickelHook` и закреплён на
конкретном коммите. При клонировании используйте `git clone --recurse-submodules`
или выполните `git submodule update --init --recursive`. CI получает его
автоматически. Дальнейшие этапы описаны в [плане](doc/plan.md).

### Локальная сборка (необязательно)

Для локальной сборки нужны Docker, Python 3 и доступ к образу
`ghcr.io/pgaskin/nickeltc:1`:

```sh
git submodule update --init --recursive
bash scripts/build-kobo.sh
python3 -m unittest discover -s tests -v
```

Скрипт пересобирает плагин из исходников, создаёт `kofm_KoboRoot.tgz` и
проверяет содержимое, права, владельца и ARM ELF. В репозитории есть старая
`libkofm.so` для сравнения; сборка заменяет её. `build.bat` — необязательный
вариант для локальной сборки на Windows, требующий Git, Docker и Python.
Исходный `build_final.py` — отдельный старый инструмент для модификации другого
архива, а не часть описанного тестового пути.

Для тестирования **сделайте резервную копию данных**. Установите NickelMenu,
скопируйте тестовый архив на устройство как `.kobo/KoboRoot.tgz`, безопасно
извлеките устройство и дождитесь установки. В меню NickelMenu появится пункт
«Файлы». Пакет содержит только плагин и пункт меню и не включает Kobalt,
локализацию, пользовательский `kofm.ini` или другие модификации. Не совмещайте
его с другим ожидающим установки `KoboRoot.tgz`, не разобравшись с его
содержимым.

Плагин рассчитан на каталог `/mnt/onboard`, как и исходный kofm. Это не
защищённая песочница: символические ссылки и операции с архивами требуют
осторожности. Не используйте тестовую сборку для важных файлов без копии.
Совместимость с конкретной прошивкой, отображение и поведение касаний нужно
проверять на устройстве; CI не заменяет такую проверку. Подробнее о настройках
и исходном прототипе — в `README_ДЛЯ_РАЗРАБОТЧИКА.txt` и `examples/kofm.ini`.
