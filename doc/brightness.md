# Свайп яркости — тестовая реализация

В основном списке проведите пальцем вдоль левого края: вверх — ярче, вниз —
темнее. Свайп распознаётся только при вертикальном движении с внешних 13%
ширины; горизонтальное движение остаётся листанием. Яркость вычисляется от
начального значения (150 процентных пунктов на высоту окна), ограничивается
0–100%. При отпускании Nickel получает запрос сохранить значение. Отмена
касания, второй палец, скрытие окна или потеря активного приложения возвращают
начальный уровень без запроса сохранения. Текущий уровень показывается внизу.
При открытых настройках, контекстном меню или подтверждении жест не работает.

Код `src/brightness.h` адаптирован из Kobalt (MIT, лицензия в
`res/KOBALT-LICENSE.txt` и в пакете), ревизия
`4e1bd56743b20751e2429ec97cc14af169c1af70`: `src/ui/brightness_gesture.h`
и `platforms/kobo/qt5/native_light.cpp`. Он использует внутренние функции
Nickel `FrontLight` и `BrightnessEventFilter`, не sysfs. Для этих объектов
используются размеры памяти 32 и 104 байта по примеру Kobalt; его документация
заявляет поддержку Qt5 с 4.38 и проверку чтения на Libra 2 с 4.38.
Пользователь сообщает, что Kobalt работает на его устройствах, но перенесённый
код Kobrowse пока не испытан на физическом Kobo.

Минимальная версия прошивки — 4.38.21908. Требуются 32-битный Nickel, все
необходимые символы и устройство с подсветкой без датчика автояркости. При
невыполнении этих условий выводится сообщение о недоступности, причина
записывается в журнал. Автояркость намеренно не меняется: реализация
`PowerSettings` из Kobalt для устройств с датчиком пока не перенесена. Проверка
символов и версии не доказывает совпадение приватного ABI на новых или старых
прошивках. Если необязательная функция определения датчика отсутствует, жест
разрешён только на известных моделях без датчика (Libra 2 и Glo HD); для других
моделей остаётся отключённым. Ошибка ABI способна нарушить работу Nickel. Перед
тестом нужна резервная копия.

Автотесты моделируют жест, отказ, отмену, разграничение с постраничной
навигацией и вызовы API через подставные объекты; они не проверяют реальные
библиотеки Nickel, сохранение яркости и аппаратную подсветку. На устройстве
нужно отдельно проверить оба направления, пределы, отмену, смену страницы,
долгое нажатие, сон, возвращение в Nickel, сохранение после перезагрузки и
отсутствие побочных эффектов. При отказе приложить журнал Kobrowse с причиной.
